### Incorrect timestamps

About **1,125 rows** were captured in real time about 07:24–07:28 while the clock was still wrong. They carry `captured_at` about 05:47:27–05:51:37, interleaved with genuine pre-shutdown rows: bucket 05:40 has 3,508 rows instead of 2,700, and bucket 05:50 has 497 instead of 180. They can be identified exactly by `received_at ≥ 2026-11-25 10:50` together with `captured_at < 2026-11-25 06:00`. **No data was changed.** Any correction (quality flag or re-stamp from the arrival order) is a separate, owner-approved data operation.

## Root causes and follow-ups

1. Every LOCAL_LAN path used one DHCP address. Interim: `nxcompat0` boot unit. Permanent: WP2c (#1734).
2. Docker endpoint loss after a failed start (#1399). Repaired by v3.2. Unattended boot and periodic repair is the follow-up.
3. The Edge deletes telemetry after the local MQTT PUBACK, and the broker queue caps at 10,000. Fix: the committed-receipt chain #1397 / #1445 / #1451 / #1449.
4. No working RTC battery and no offline time source. Fix: WP2e (#1741, runbook `time-source.md`).
5. Recovery tooling defects found during the incident: v1 alias on NetworkManager-tracked `lo`, buffered output, root-only Compose files, false port check. All fixed with regression tests (#1745, #1746).

Still open: one more persistent Edge broker session remains disconnected with a full queue (`store/messages/count` 10,152, `clients/disconnected` 1). It still drops about 277 msg/min for **that** consumer, not for central. Its client ID needs the broker log (owner).
